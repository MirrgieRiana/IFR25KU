# リリース

リリースは、`v` で始まるタグの push 時にのみ、`release` ワークフローによって開始されます。

## リリースの手順

リリースの手順は、すべて、人間が手動で操作して行います。
AI エージェントは、たとえその権限が物理的に与えられていたとしても、リリースの手順を実行してはいけません。

1. バージョンを決定します。
2. CHANGELOG の「未リリース」セクションの見出しをバージョン番号で更新します。
   - 詳細は changelog スキルを参照してください。
3. デフォルトブランチの上で `gradle.properties` の `mod_version` を `v` なしのバージョン番号で更新してコミットします。
   - コミットタイトルは `v` 付きのバージョン番号のみで構成します。
   - コミットメッセージは空欄にします。
4. `v` 付きのバージョン番号の名前を持つタグを作成します。
5. デフォルトブランチに push します。

---

これにより、以下の場所が更新されます。

- GitHub Releases の作成と成果物のアップロード
- Modrinth への成果物のアップロード
- CurseForge への成果物のアップロード

配布サイトのトップページに記載される Mod の説明文は更新されません。

## バージョン

バージョンは、原則として SEMVER と似ていますが、以下の点で異なります。

- メジャーバージョンの更新時に、マイナーバージョンが1増える。
- メジャーバージョンの更新時に、メジャーバージョンは1増えるのではなく、新しいマイナーバージョンと同じ値になる。

これによって、バージョンの欠番が大量に生じますが、それ以外の性質は SEMVER と一致します。

---

ワールドデータの互換性を失わせる変更をした場合は、メジャーバージョンリリースです。
コンテンツの削除や、レシピや地形生成物の変更によって新旧のデータを混ぜるとゲームバランスが破壊される場合などです。

修正の範疇を超えた、仕様やコンテンツの追加や変更を行った場合は、マイナーバージョンリリースです。
コンテンツの追加は、サーバーとクライアントの間の接続の互換性を失わせますが、マイナーバージョンリリースとして扱います。

パッチバージョンは、実際に修正が行われたか否かにかかわらず、リリースの度にインクリメントします。

必要に応じて、alpha や beta のバージョンがリリースされる場合もあります。
主に、環境移行時の実験的なリリースです。

---

例えば、10.15.6 の次のバージョンは、もっぱら、次の3通りに分かれます。

- 16.16.0 - メジャーバージョンリリース
- 10.16.0 - マイナーバージョンリリース
- 10.15.1 - パッチバージョンリリース

### コンテンツのバージョン

この MOD では、コンテンツの実装の前進度合いを、v16 のような単調増加する整数で呼称します。
これはマイナーバージョンの値に対応します。
